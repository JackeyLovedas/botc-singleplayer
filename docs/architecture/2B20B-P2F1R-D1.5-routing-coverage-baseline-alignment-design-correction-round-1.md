## 6. Complete tuple universe and loss classification

### 6.1 Canonical tuple identities and hit state

The producer parses every source entry in each complete `coverage-final.json`; a zero-hit-only summary is insufficient. Each semantic obligation identity excludes its hit state. Each persisted tuple appends exactly one `HitState`:

```text
HitState = ZERO | POSITIVE
```

Any finite non-negative safe-integer hit count equal to zero maps to `ZERO`; any value greater than zero maps to `POSITIVE`. Negative, fractional, non-finite, absent, duplicate, or mismatched counts fail closed.

Each tuple is one compact JSON array, serialized with no insignificant whitespace, followed by LF. Fields and order are exact:

```text
["STATEMENT",path,startLine,startColumn,endLine,endColumn,hitState]
["FUNCTION",path,name,declStartLine,declStartColumn,declEndLine,declEndColumn,locStartLine,locStartColumn,locEndLine,locEndColumn,hitState]
["LINE",path,line,hitState]
["BRANCH_ARM",path,branchType,branchStartLine,branchStartColumn,branchEndLine,branchEndColumn,armIndex,armStartLine,armStartColumn,armEndLine,armEndColumn,hitState]
```

`path` is repository-relative POSIX. String values use JSON escaping. Coordinates, line, and arm index are non-negative safe integers. Semantic identity is the same tuple without the final `hitState`. Lines are derived exactly as the maximum statement hit count for each statement-start line, matching current behavior. Duplicate semantic identities, missing hit maps, mismatched branch arm counts, sparse arrays, or incomplete source maps fail closed.

For each kind, semantic tuples are sorted by the existing ordinal comparator over their canonical compact bytes. The complete map concatenates kinds in exact order `STATEMENT`, `FUNCTION`, `LINE`, `BRANCH_ARM`. Per-kind count/SHA and full-map SHA cover complete maps, not merely uncovered tuples. UTF-8, LF, no BOM, no locale, no absolute path, no timestamp, and no insertion-order dependency are mandatory.

### 6.2 Source census and classification universe

The old-to-S production census is exact:

```text
unchanged paths=62
modified paths=1
added paths=6
removed paths=0
```

The sole modified path and blob binding are:

```text
packages/domain-core/src/index.ts
old blob=944cbc2a8a80510ade3683fc46fa956d3923387e
new blob=e6e6878254d9809fb402c22cbc94e72c5172f774
```

Every semantic identity in the set union of old and new complete tuple maps receives exactly one record. The record keys are ordered:

```text
classification,kind,identity,oldHitState,newHitState,sourcePath,reason
```

The closed, mutually exclusive and exhaustive `classification` union is:

- `UNCHANGED_IDENTITY`: identity exists in both maps and its source blob is identical.
- `CHANGED_IDENTITY`: identity exists in one or both maps and its source is the single modified `index.ts` blob pair.
- `EXPECTED_ADDITION`: identity exists only in new and its source is one of the six exact added paths.
- `REMOVED_IDENTITY`: identity belongs to a source path removed from the production tree.
- `MISSING_IDENTITY`: identity exists only in old although its source blob is unchanged.
- `UNEXPECTED_IDENTITY`: every new-only identity not covered by `CHANGED_IDENTITY` or `EXPECTED_ADDITION`, or any identity whose source census/binding is contradictory.

`oldHitState` or `newHitState` is `NONE` only when the identity does not exist on that side. `reason` is one of the same six tokens; free text is forbidden. Classification precedence is `REMOVED_IDENTITY`, `MISSING_IDENTITY`, `EXPECTED_ADDITION`, `CHANGED_IDENTITY`, `UNCHANGED_IDENTITY`, then `UNEXPECTED_IDENTITY`. This precedence is used only after exact set-membership and blob checks; it cannot hide contradictions.

The acceptance conditions are:

```text
removedSourceCount=0
REMOVED_IDENTITY=0
MISSING_IDENTITY=0
UNEXPECTED_IDENTITY=0
unclassifiedIdentity=0
contradictoryIdentity=0
stablePositiveBecameZero=0
modifiedPositiveBecameZero=0

```

`EXPECTED_ADDITION` is allowed only for the six new source paths. `CHANGED_IDENTITY` is allowed only for `packages/domain-core/src/index.ts`; its actual count and tuple SHA are Implementation Actual Bindings. Any old `POSITIVE` tuple absent in new, or present as `ZERO`, is an obligation loss and fails even on the modified path.

### 6.3 Relocation policy

```text
relocationAllowed=false
```

D1.5 has no source-map or semantic relocation authority. Location-only similarity, equal text, equal function name, or equal tuple count never pairs two identities. An old positive identity removed from `index.ts` cannot be discharged by a new identity at another location. Delete/add equal-count substitution remains two separate records and fails if the deleted old identity was positive. This conservative policy is bounded to this one migration and is not a generic coverage-intelligence system.
