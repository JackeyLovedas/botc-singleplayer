## 3. Structural complexity budgets

### 3.1 Permanent files

Permanent additions are limited to:

1. one pure-data coverage-profile registry module; and
2. one new P profile artifact.

All other permanent file additions are zero. Any existing script or selector
modified by a future implementation must be in the final design's exact
allowlist. A second registry, new CLI, workflow, job, matrix, runner,
dependency, test file, or test identity is prohibited.

### 3.2 Registry

The registry is limited to one module, with 17 records at S and 18 records at
P. Its schema version is `botc-coverage-profile-registry-v3`. Each record has
the final design's 15 exact ordered fields, and the module exposes only the
final design's four readonly exports.

The registry has no I/O, Git call, filesystem call, mutation API, registration
API, callback, fallback, `latest` selection, dynamic selector, automatic
migration, source parsing, or CLI. Static profile-metadata line count is not a
complexity-failure condition.
