The coverage verifier gains two closed D1.5 operations:

```text

--verify-d1-5-profile-child ACCEPTED_1712_V1
```

`ACCEPTED_OLD_AUTHORITY_PATH` and `SOURCE_HEAD_S_AUTHORITY_PATH` are command-grammar parameter tokens, not literal values or unresolved design placeholders. Each consumes exactly one CLI argument naming an existing regular JSON coverage-authority file. `ACCEPTED_OLD_AUTHORITY_PATH` must resolve to the authority freshly reproduced at source HEAD `4d576e205cb20c37ba913b923a1cd39e8d800d18` and must pass all old-profile count and SHA checks below. `SOURCE_HEAD_S_AUTHORITY_PATH` must resolve to the segmented coverage authority generated from the current full `SOURCE_HEAD_S`. The verifier normalizes neither version identity nor authority contents from the paths; it validates both files against their exact contracts and fails closed on a missing file, directory, non-JSON input, extra positional argument, wrong source HEAD, or hash mismatch.

Paths may identify evidence inputs, but the version token is exact. Neither operation may support `latest`, fallback selection, prefix matching, environment-driven selection, or automatic version inference.

The emit operation returns canonical profile and audit material to stdout without modifying repository files. Its output is fully determined by the two validated coverage authorities and `SOURCE_HEAD_S`; the implementer chooses no counts, hashes, tuple classifications, or profile fields.

## 13. Rollback

Rollback is additive and history-preserving:

- If Stage P fails before acceptance, revert P. This removes the new selector/profile child while leaving S available for diagnosis.
- If the slice is abandoned, revert P and then S in reverse order.
- Never edit or delete the historical 1572 baseline, D1 candidate, or old profiles.
- Never rewrite Git history to hide failed profile generation.
- Temporary worktrees and generated artifacts may be deleted only after their required evidence is archived and hashes are reverified.
- A rollback result has no Hosted or PR acceptance unless separately published and checked.

## 15. Alternatives, tradeoffs, and revisit triggers

Rejected alternatives:

- Mutating `ACCEPTED_1572_V1`: destroys historical provenance.
- Treating green 1712 tests as implicit promotion: conflates execution with governance.
- Creating the profile at S: creates an impossible source-HEAD self-reference.
- Selecting the newest profile automatically: makes replay and CI meaning depend on registry order.
- Adding new groups or filters: expands topology without need.
- Modifying ownership verifiers: reopens the already-frozen D1 ownership boundary.
- Adding a generic profile migration framework: exceeds this one-use migration.
- Continuing the existing D2 corrections: uses a stale workflow blob and exhausted correction budget.

Chosen tradeoff:

- Two commits and a disposable old-source coverage run add operational cost, but provide executable source provenance, complete loss detection, append-only profile safety, and deterministic rollback without changing product behavior.

Revisit only if:
