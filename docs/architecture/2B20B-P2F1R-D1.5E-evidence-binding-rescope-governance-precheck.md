## 3. Problem statement

Correction Round 2 made the five graph nodes internally acyclic: `SOURCE_HEAD_S`, `OLD_PROFILE`, `DELTA_RECORD`, `ACCEPTED_1712_PROFILE`, and `PROFILE_CHILD_P`. That internal DAG does not close the mandatory repository evidence binding.

The frozen contract requires the final graph manifest to be generated only after P exists and to bind the exact `PROFILE_CHILD_P` OID. It also requires that manifest SHA to be recorded in implementation traceability and the archived migration record. The inherited Stage-P allowlist, however, places those repository documents inside P.

The sequence is therefore unreachable:

1. Commit P.
2. Generate a manifest that binds P and compute its SHA.
3. Write that SHA into a document already required to be part of P.

Amending P creates P' and invalidates the manifest. Prewriting P creates a future-commit self-reference. Adding an undefined Q makes P no longer the final evidence HEAD and violates the frozen S→P terminal contract and allowlist. The graph is acyclic, but the mandatory repository writeback outside the graph reintroduces a P/manifest cycle.

This is a frozen-contract reachability defect, not an implementation defect, BOTC rule question, coverage-quality question, or permission to create Design Correction Round 3.

## 4. Options and tradeoffs

### Option A — P plus repository-external final evidence only

P remains the final repository commit. After P exists, the child verifier writes the graph manifest and direct artifact hashes only outside Git. The external evidence bundle binds P; P documents contain expected contracts only and never claim the actual manifest SHA.

Advantages:

- smallest commit graph;
- no repository self-reference;
- preserves the original S→P history;
- no additional repository file or framework.

Costs and rejection reason:

- the only final binding is operational state outside the repository;
- future D2 cannot use a durable repository ancestor containing the exact P-bound evidence;
- retention, checkout portability, and later independent reread depend on an external location whose custody is not yet frozen;
- it fails the user's requested durable, reviewable evidence-boundary objective unless a separate external archival authority is designed.

Option A is technically acyclic but is not the recommended durable repository model.

### Option B — three-stage S→P→E plus external exact-E review

S materializes migration inputs and temporary producer evidence. P is the direct child of S and materializes the accepted 1712 baseline/profile, exact static selector, and final non-evidence product/configuration state. E is one direct, single-parent, docs/evidence-only child of P. E stores the P-bound manifest and the implementation traceability/audit records that can exist only after P exists. E records P and direct artifact identities, never E. A fresh independent review occurs after E exists and binds exact E outside E.

Advantages:

- every dependency points from an already existing object to a later object;
- P's OID remains immutable after manifest generation;
- final repository evidence is durable and checkout-portable;
- E is a bounded archive stage rather than a permanent runtime framework;
- future D2 has one unambiguous repository baseline while retaining P as product/profile authority;
- final review can bind the actual final repository head E without a commit after review.

Costs:

- one additional docs/evidence-only commit;
- D1.5E must explicitly rescope final-head, allowlist, lifecycle, review, and rollback contracts;
- exact-head review authority becomes E, while product/profile artifact authority remains P, so the distinction must be explicit everywhere.

Option B is the recommended model.

### Option C — amend P, prewrite P, or add a self-hashing evidence record

Rejected. Amending P invalidates the old P-bound manifest. Prewriting P is an impossible future-OID self-reference. A document containing its own Git OID or final byte digest is recursive. A hash whose only authority is another hash, a manifest whose only payload is another manifest, or a snapshot that requires a later snapshot to validate the earlier snapshot merely moves the cycle.

### Option D — undefined Q, mutable tag/note, or permanent evidence framework

Rejected. An unnamed Q bypasses the exhausted design contract. A mutable tag or note is not the reviewed repository tree and does not satisfy the exact-head evidence chain. A new dynamic graph, evidence database, manifest-of-manifest system, or runtime dependency framework is disproportionate and violates the bounded migration lifecycle.

## 5. Recommended three-stage binding

The bounded D1.5E design should freeze exactly this ancestry:

```text
SOURCE_HEAD_S
    |
    v
PROFILE_CHILD_P
    |
    v
EVIDENCE_HEAD_E
    |
    v
fresh external independent review bound to E
```

Exact governance meaning:

- `parent(P)=S`.
- `parent(E)=P`.
- P and E each have exactly one parent.
- S contains no future P or E OID.
- P may bind S and artifacts already available before P, but contains neither P nor E OID.
- The P-bound manifest is generated only after P exists.
- E may record the exact P OID, the P-bound manifest bytes, and direct SHA-256 values for concrete S/P artifacts.
- E must not contain, predict, derive, or reserve the E OID.
- No commit amends or rewrites S or P.
- A fresh independent reviewer receives the actual E OID after E exists. The reviewer report, and later GitHub review comments if separately authorized, bind E outside E.
- No commit follows a passing final review. Any later commit invalidates that review under `REVIEW_PROTOCOL.md`.

`EVIDENCE_HEAD_E` is not a third product stage, a coverage profile source, a runtime selector, or a replacement for P. It is the bounded repository evidence stage required solely because P-dependent facts cannot be written into P.

## 6. Authority separation

The future bounded design must preserve four non-interchangeable authorities:

1. **Product/profile authority — P**: the accepted 1712 baseline/profile entry, exact one-token selector state, and any retained stable verifier behavior are authoritative from P's tree. E cannot modify or reinterpret them.
2. **Repository evidence anchor — E**: E archives the exact manifest and traceability/audit facts that directly bind P and its concrete artifacts. E is authoritative only for that evidence chain.
3. **Final-review authority — external review bound to E**: the fresh reviewer output names exact E after E exists. The report is not reconstructed or prewritten inside E.
4. **Future D2 baseline — E as ancestry, P as product input**: a separately authorized D2 must start from E so the evidence archive is in its ancestry, but it must read the actual accepted profile/configuration from P-bound artifacts. D2 cannot treat E as runtime/profile authority.

A digest proves exact bytes, not acceptance, correctness, BOTC rules, product behavior, or trusted history. Git ancestry proves commit relation, not coverage quality. Green coverage cannot substitute for either rule truth or independent review.

## 7. No-cycle proof

The proposed dependency edges are:

```text
S bytes/OID -> P content
P bytes/OID -> E evidence content
E bytes/OID -> external fresh-review record
```

There is no reverse edge:

- S never contains P or E.
- P never contains P, E, or a P-bound manifest SHA.
- E contains P and direct hashes of concrete artifacts, but never E.
- The external review contains E only after E exists and is not an input to E.

Git naturally computes E's OID from E's parent and tree after E is created. Because E's tree does not contain E's OID, that Git binding is not a self-reference.

The evidence layer must use one direct digest per concrete artifact. It must not create a digest whose only payload is another digest, a second manifest whose only payload is the first manifest, an evidence-bundle self-digest stored inside that same bundle, a snapshot-of-snapshot chain, or a later object that requires writeback into an earlier commit. The repository's normal Git object graph and the direct artifact hashes are sufficient.

The required regression proof for a later design is exact:

1. Capture P OID before manifest creation.
2. Generate and archive the P-bound manifest without changing P.
3. Commit E with parent P and the allowed evidence files only.
4. Re-read P OID and require byte-for-byte equality with step 1.
5. Verify the manifest's P OID, direct artifact SHA values, and E-archived bytes.
6. Reject any attempted writeback/amend of P.
7. Verify `parent(E)=P`, E has one parent, and E changes only the frozen evidence allowlist.
8. Run fresh independent review at exact E; require the report's reviewed head to equal E.
