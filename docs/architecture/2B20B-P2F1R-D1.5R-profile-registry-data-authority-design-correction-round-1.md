## 4. Artifact-reference union and authority separation

### 4.1 Exact reference shape

Each metadata record contains `artifactReference` with exactly these ordered
keys:

```text
kind
path
artifactId
byteLength
sha256
```

The closed `kind` union is:

```text
LEGACY_IN_VERIFIER_V1
PROFILE_JSON_V1
```

For `LEGACY_IN_VERIFIER_V1`:

- `path` is exactly `scripts/verify-coverage-obligations.mjs`;
- `artifactId` equals `profileId`;
- `byteLength` and `sha256` bind the canonical JSON data serialization of the
  already-existing in-memory frozen profile object, not a JavaScript source
  span;
- the verifier resolves the artifact from its existing local historical array
  by exact ID and validates the canonical data identity directly;
- no runtime source read, marker, span, suffix, offset, or JavaScript parse is
  allowed.

For `PROFILE_JSON_V1`:

- `path` is exactly
  `docs/implementation/coverage-profiles/phase-3-slice-2b20b-p2f1r-d1-5r-<first7(actual-S)>-routing-coverage-v1.json`;
- `artifactId` equals the filename stem and record `profileId`;
- `byteLength` and `sha256` bind the complete file bytes;
- the verifier uses its S-resident closed JSON-artifact validator and explicit
  repository-relative path resolver; P changes no verifier logic.

After validation, the S-resident reader exposes one recursively frozen
comparison view with exact keys `id,sourceHead,sourceKind,topology,obligations`,
where `id` is the file's validated `profileId`. This view exists only in
memory; it is neither another artifact nor a registry record, and it makes the
existing obligation comparison consume legacy and JSON artifacts through one
closed value shape without copying data into the registry.

`<first7(actual-S)>` is evaluated only after S exists. No future value is
reserved or predicted in this document.

### 4.2 Link/import contract

At S, `scripts/verify-coverage-obligations.mjs` directly imports only metadata
records and the selector map. Its historical artifact array remains local and
byte-identical. It resolves every legacy record by exact ID, then requires
record source HEAD, canonical byte length, canonical data SHA, available
counts/hashes, and local artifact fields to agree.

The verifier also contains, before coverage and P, the bounded
`PROFILE_JSON_V1` reader/validator. It accepts only the exact P path selected by
one metadata record. It rejects path escape, symlink/junction, non-file,
missing file, duplicate artifact ID, wrong ID, wrong source HEAD, byte-length
mismatch, SHA mismatch, schema mismatch, and selector/reference mismatch.

Closed diagnostics are:

### 4.3 Three authorities

1. **Profile Artifact Authority**: the historical frozen object in the verifier
   for legacy records, or the exact standalone JSON file added by P for the new
   record. Registry metadata cannot alter either body.
2. **Registry Metadata Authority**: records, provenance, lifecycle,
   eligibility, references, and the one selector map in
   `scripts/coverage-profile-registry.mjs`.
3. **Evidence Authority**: E's three docs/evidence files. E cannot select,
   load, mutate, substitute, or reinterpret an artifact or registry record.

P is the sole authority commit for the new JSON artifact and active metadata.
E is never artifact or selector authority.

## 8. Versioned artifact contracts

### 8.1 Canonical byte serialization

Both legacy canonical data identities and `PROFILE_JSON_V1` use:

```text
serialization=JSON.stringify(validatedPlainData, null, 2) + "\n"
encoding=UTF-8
BOM=forbidden
lineEnding=LF
indent=two ASCII spaces
trailingWhitespace=forbidden
terminalLF=exactly one
objectKeyOrder=the closed schema order
arrayOrder=the validated dense contract order
hashPreimage=the complete serialized UTF-8 byte sequence
hash=lowercase SHA-256 of hashPreimage
```

Input must be recursively frozen before serialization. Missing, unknown,
extra, duplicate, or reordered keys; sparse arrays; holes; accessors; symbols;
cycles; proxies; non-plain objects; mutable nested values; unsafe/non-finite
numbers; CR; BOM; invalid UTF-8; wrong terminal LF; wrong ID/source; wrong
length/hash; and one-byte mutation reject.

### 8.2 Legacy union

The 17 legacy artifacts remain their existing in-verifier objects. Their
closed top-level variants are:

```text
L1=id,sourceHead,sourceKind,obligations
L2=id,sourceHead,sourceKind,supersedesForTopology,supersessionReason,obligations
L3=id,sourceHead,sourceKind,supersedesForTopology,supersessionReason,removedObligationAudit,obligations
L4=id,sourceHead,sourceKind,supersedesForTopology,supersessionReason,topology,obligations
L5=id,sourceHead,sourceKind,topology,obligations
```

`removedObligationAudit` has exact ordered keys
`canonicalTuple,baselineHit,candidateHit,auditArtifactSha256`.
`obligations` always has exact ordered keys
`sourceFiles,zeroHitStatements,zeroHitFunctions,zeroHitLines,zeroHitBranchArms`;
each child has exact ordered keys `count,sha256`.

Legacy topology subvariants are closed by the exact per-record canonical
preimage length/SHA in section 6.2. The validator first requires recursively

serializes the entire nested object. Any nested key/value/order/array change
changes the frozen preimage and fails length/SHA equality. Thus heterogeneous
legacy variants remain executable without copying their bodies into the
registry or parsing their source.
