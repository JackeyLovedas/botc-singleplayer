## 3. Exact source-materializer CLI

The only source-profile producer invocation is:

```text
node scripts/verify-coverage-obligations.mjs \
  --emit-d1-5p-source-profile \
  SOURCE_HEAD_S \
  OLD_GLOBAL_MANIFEST_PATH \
  OLD_COVERAGE_FINAL_PATH \
  SOURCE_GLOBAL_MANIFEST_PATH \
  SOURCE_COVERAGE_FINAL_PATH \
  D1_CANDIDATE_INVENTORY_PATH \
  EMPTY_OUTPUT_DIRECTORY
```

`process.argv.slice(2)` contains exactly eight strings: the mode plus seven
operands in the displayed order.

Operand contracts:

1. `SOURCE_HEAD_S`: exact lowercase 40-hex current clean HEAD.
2. `OLD_GLOBAL_MANIFEST_PATH`: explicitly supplied existing non-symlink
   regular file.
3. `OLD_COVERAGE_FINAL_PATH`: explicitly supplied existing non-symlink regular
   file.
4. `SOURCE_GLOBAL_MANIFEST_PATH`: explicit file from the sole completed S
   capture.
5. `SOURCE_COVERAGE_FINAL_PATH`: explicit file from that same S capture.
6. `D1_CANDIDATE_INVENTORY_PATH`: explicit canonical D1 candidate file.
7. `EMPTY_OUTPUT_DIRECTORY`: existing empty real OS-temp directory outside the
   repository.

Forbidden:

- missing, extra, reordered, aliased, or prefixed operands;
- `latest`, globbing, directory scans, environment selection, sibling
  inference, default paths, or worktree-root inference;
- treating a temp path or filename as source identity;
- directories, symlinks, junctions, devices, pipes, sockets, escapes, mixed
  capture roots, or partial files.

The materializer performs no network access, coverage execution, old-head
checkout, worktree creation, or repository write.

## 6. Exact outputs and deterministic repeat

The producer creates exactly four files and no others:

```text
delta-record.json
profile-candidate.json
profile-entry.mjsfrag
tuple-census.json
```

Writes use exclusive creation, same-directory temporary files, complete
write/fsync/close, reread/hash verification, and atomic no-replace
publication.

Success:

- exit `0`;
- empty stderr;
- exactly one LF-terminated stdout line:

```text
D15P_SOURCE_PROFILE_EMITTED SOURCE_HEAD_S oldGlobalSha256 oldCoverageSha256 sourceGlobalSha256 sourceCoverageSha256 deltaRecordSha256 profileCandidateSha256 profileEntrySha256 tupleCensusSha256
```

Validation failure:

- exit `1`;
- empty stdout;
- exactly one diagnostic token plus LF.

Unexpected internal failure:

- exit `2`;
- empty stdout;
- `D15P_INTERNAL_FAILURE\n`.

Output contains no path, artifact body, title, timestamp, PID, environment
value, stack, random value, or locale text.

Deterministic-repeat authority reuses the same single S capture and the same
authenticated historical byte carriers in a second new empty output directory.
It does not rerun coverage. All four files and stdout must be byte-identical.

1. exact authenticated old inputs pass;
2. identical files in different directories produce identical output;
3. OS-temp location grants no authority before authentication;
4. `latest`, scan, environment, omitted path, reordered path, and inferred
   sibling reject;
5. one-byte old manifest mutation rejects on direct hash before schema use;
6. one-byte old coverage mutation rejects on direct hash;
7. correct hash cannot accompany partial, substituted, extra-source,
   missing-source, wrong-group, or wrong-count content;
8. wrong immutable profile object bytes/hash reject;
9. source and old inputs cannot be swapped;

11. missing historical preimage yields no old-head execution and stops;
12. deterministic repeat uses the same single S capture and produces identical

13. collisions preserve existing targets and remove partial temporary files;

## 9. B02 verifier-budget correction

Parent section 16:

```text
verify-d1-5e-evidence-binding.mjs <=900 LOC and <=131072 bytes
```

is replaced only by:

```text
scripts/verify-d1-5e-evidence-binding.mjs physicalLfLines<=360
scripts/verify-d1-5e-evidence-binding.mjs gitBlobBytes<=65536
```

All other file, LOC, byte, allowlist, and lifecycle budgets remain unchanged.

Measurement is Git-object authoritative:

1. Resolve the S blob with
   `git rev-parse S:scripts/verify-d1-5e-evidence-binding.mjs`.
2. Obtain raw bytes through
   `git show S:scripts/verify-d1-5e-evidence-binding.mjs`.
3. Require UTF-8, LF, no BOM, no CR, and exactly one terminal LF.
4. `physicalLfLines` is the raw count of byte `0x0A` from that `git show` blob
   output.
5. Obtain byte size through
   `git cat-file -s S:scripts/verify-d1-5e-evidence-binding.mjs`.
6. Require the exact blob IDs at S, P, and E to be equal.

Checkout conversions, editor counts, filesystem sizes, generated reports, or
working-tree line endings are not authority.

No sibling helper, imported local helper, generated string, base64 executable,
`eval`, dynamic import, documentation code, or profile payload may displace
verifier logic to evade either ceiling. The verifier remains one self-contained
Node-standard-library file and remains byte-identical through E.
