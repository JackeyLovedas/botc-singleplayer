## 4. Concrete failed paths

### 4.1 First candidate

`8c24458...` searched for the selected object marker and then for
`\n  })\n]);\n\nfunction parseArguments`. The profile was accepted only when the next
top-level symbol and whitespace matched. The mechanism did not authenticate a
registry; it authenticated one whole-file layout.

### 4.2 Repair Round 2 candidate

`10023c0...` shortened the suffix to `\n  })\n]);` but then searched the
entire remaining verifier for another occurrence. A later unrelated array
close satisfied the same text, so a valid historical object failed. Removing
only that search did not cure the authority error because the first suffix
remained a source-layout guess.

### 4.3 Stop-loss candidate

`77a43dc...` replaced the global suffix scan with registry and profile markers,
a fixed 2930-byte span, a four-byte close offset, and exact punctuation. This
still made the historical profile legal only while it was the last object.
The required P operation is to append another profile, so the sentinel's
required adjacent `\n]);` would be false in the intended terminal state. Its
self-test also read its own source, reconstructed the same offsets, and
asserted a following class prefix. The mechanism therefore escaped the
registry it was intended to bound.
